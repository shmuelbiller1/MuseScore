# Personal Voice Choir Studio — experimental offline sidecar

**Status: proof of concept, not a finished in-app choir instrument.** No claim of realistic voices. Four licensed human singers (eight short and longer vowel excerpts) have now been processed and **objectively measured for F0 only**; there has been no controlled human listening evaluation of realism, vocal age, register character or artifact severity. The examples include both synthetic tests and real recorded singing vowels with explicit [CC BY 4.0 attribution](examples/vocalset/ATTRIBUTION.md). This experimental sidecar deliberately avoids modifying MuseScore's audio engine, mixer, score or project storage until sound quality and score-event fidelity can be evaluated.

## Run offline

1. In MuseScore, open a four-part score and export a **MIDI** file (File → Export → MIDI). Ensure the four parts have their own MIDI tracks. If playback-dependent details matter, audition the exported MIDI: this tool uses the MIDI's note-on/off, velocity, and tempo events as its sole timing/pitch authority, **not** the live score renderer. Some engraving semantics (fermata duration, articulation, historically marked dynamics) may be lost or simplified by MIDI export. This tool does not promise to preserve them beyond what MuseScore exports.
2. In the portable Windows ZIP, extract it and choose **Help → Personal Voice Choir Studio (experimental)…** in MuseScore. This opens the bundled `App/MuseScore/choir-studio/index.html` in your default browser. Alternatively open that file directly; from a source checkout, open `share/choir-studio/index.html`. No server, install, account, internet access, models or remote assets are required. Microphone capture requires browser permission and a secure context; if denied, import a WAV. No data is transmitted by this page.
3. Record a clear, steady **vowel** or import your own WAV (under 90 seconds). Choose the recorded vowel's start/end in each part, or enter its measured source Hz if auto-detection fails. Import or record several source vowels for different registers when possible. You can listen to and save the unchanged original separately from processed output. Browser microphone captures are commonly WebM or Ogg: **Save original capture** retains the exact capture; **Save reimportable WAV** exports a 24 kHz mono PCM copy you can load again. In-memory session data is cleared when you close/reload the page; save recordings you wish to keep.
4. Load the exported `.mid` file; assign **four different MIDI note tracks** to Soprano, Alto, Tenor and Bass. Each has independent source recording, pitch correction, nominal formant, brightness/warmth/breathiness/resonance/strength, volume/pan, variation, mute and solo. A 100% correction target matches the MIDI pitch approximately; below 100% is intentionally expressive **and no longer guarantees written pitch**. To maintain exact intended pitch choose 100%. The formant control is an approximate spectral shaping parameter, **not independent measured formant tracking**. Bass uses its own note events, not transposed soprano notes.
5. Render the complete score when it fits within the explicit **4-minute memory limit**; longer scores fail with an error rather than silently losing later notes. Listen against the original and download a 24 kHz stereo WAV. When the output-to-source pitch ratio exceeds 1.7 or is below 0.59, use a closer-register recording. Warnings do not mean the result will sound natural within the range. This renderer cannot produce lyrics or trained vocal identities. Playback and export are performed entirely in browser memory; the processed WAV is not injected into MuseScore playback or stored with a project.

## Real-singer proof and its limits

Four attributed VocalSet singers are bundled **only as an optional offline demonstration**, not as an implicit default voicebank. Prefer the four `*-long-a.wav` files in `examples/vocalset/`: import them together, inspect the source assignment and load `examples/four-independent-real-registers.mid`. For a direct before/after, play `examples/vocalset/soprano-f1-long-a.wav` then `examples/after-long-soprano-A4.wav`; `examples/four-part-long-vowel-mix.wav` is the complete example. It has four distinct note tracks including bass A2, and uses source excerpts nearer each register. **Original source clips, exact hashes, offsets, licence and processing changes** are listed in [ATTRIBUTION.md](examples/vocalset/ATTRIBUTION.md). You may choose your **own** recording instead.

`node share/choir-studio/examples/evaluate-long.cjs` reproduces the longer-excerpt mix and [objective measurements](examples/long-vowel-metrics.json). On four isolated steady first notes, measured F0 errors are −0.2, −1.6, −0.4 and −1.1 cents respectively at 24 kHz; no extreme-shift warning. The previous 80 ms clips and their [short-clip measurements](examples/real-vowel-metrics.json) are retained for contrast, **not recommended as a natural-sounding voicebank**; the short alto excerpt triggers an extreme-shift warning. These measurements establish neither natural timbre nor perceived pitch on attacks or rapid phrases. **A proper blind perceptual evaluation using longer consented phrases, cross-register singers, listeners and phonetic material remains outstanding.**

The renderer uses a small, deterministic period-synchronous overlap-add grain process and simple filters. Grain spacing targets written F0 while source grains play at their original sample rate. Local waveform-phase correlation tracks the singer's period variations and is cached across notes; this fixes accumulated phase drift observed with the longer excerpts. Unlike a full PSOLA implementation, it does **not** identify glottal closure instants, handle consonants, de-ess or track time-varying formants. It can phase, buzz, sound synthetic, or shift pitch at attacks, and estimates a *single* steady source F0. Synthetic tests establish approximate sustained-note pitch, timing, non-silence, mute/solo and output-byte determinism; they do not establish perceptual quality. Playback of rapid tempo transitions and very short notes has not been perceptually validated.

## Why not bundle a third-party processor or vocal model?

The following upstream primary sources were read in November 2026; none of these components is included here. Licensing and Windows feasibility alone cannot establish expressive quality.

| Approach | Verified terms & Windows evidence | Quality and resource tradeoff |
| --- | --- | --- |
| [Rubber Band Library](https://github.com/breakfastquay/rubberband/blob/master/README.md) | Its README states GPL version 2 **or later** (compatible in principle with this GPLv3 application when using that option), or commercial licensing; its [build guide](https://github.com/breakfastquay/rubberband/blob/master/COMPILING.md) documents Windows builds and a single-file built-in FFT/resampler option. Other FFT/backends have separate license obligations. | Offline professional time stretch/pitch shift option; **independent formant shifting and convincing choir output have not been verified here**. Native library adds build and CPU cost. |
| [aubio](https://github.com/aubio/aubio/blob/master/COPYING) | GPLv3 as indicated by its COPYING; its [README](https://github.com/aubio/aubio/blob/master/README.md) describes pitch analysis, phase vocoder and Windows AppVeyor. | Primarily analysis building blocks, not a turnkey singer; extra DSP implementation, FFT CPU and validation required. |
| [JUCE framework](https://github.com/juce-framework/JUCE/blob/master/LICENSE.md) | Its LICENSE.md describes **AGPLv3 or commercial** terms, not a blanket GPLv3 grant. It describes a cross-platform desktop framework. | Framework overhead, not by itself a licensed singing model or a formant-preserving transform. Not selected; AGPL integration review would be required. |
| Local browser-native PSOLA-like grains (implemented here) | This new source code is GPL-3.0-only like the project. Uses built-in browser Web Audio and MediaRecorder; no linked libraries or model assets. Four optional singers' short and longer vowel excerpts are separately licensed CC BY 4.0 with attribution; browser support and local-file microphone permissions vary. | Low installation cost; only a steady vowel and approximate spectrum; pitch metrics from four real vowels do **not** establish perceived quality. |

The existing MS Basic soundfont licence does **not** license use of any third-party singer samples. The eight included singer excerpts come from VocalSet, whose [primary Zenodo metadata](https://zenodo.org/api/records/1442513) confirms CC BY 4.0; their source transformation and hashes are documented alongside them. No unverified model or recording is bundled. To upgrade to a reliable in-app voice instrument: test multiple consented real recordings across each register, measure pitch/error and consonant preservation, assess timbre blind with listeners, investigate a redistribution-compatible processor and Windows build, then implement a per-track event source through the existing audio-engine interfaces and project persistence. Do not treat this sidecar as a completed replacement.

## Resource probe (not a Windows result)

On this Linux x64 sandbox with Node 22, `node share/choir-studio/examples/benchmark.cjs` rendered 960 synthetic note events across ~120 seconds of 24 kHz stereo score-aligned audio in about 0.25 seconds; resident process size changed from ~41 MB to roughly 85–100 MB in repeated runs. This is **not** a peak-memory measurement, browser timing, perceptual measurement or portable-Windows verification. The actual cost varies with score density, input length, device and browser. The 4-minute cap limits in-browser allocation; longer scores fail visibly instead of truncating.

## Developer checks

```sh
node share/choir-studio/examples/generate.cjs  # regenerate the synthetic before/after WAV and MIDI
node share/choir-studio/examples/evaluate-real.cjs  # short-clip F0 measurements; NOT realism
node share/choir-studio/examples/evaluate-long.cjs  # longer-excerpt F0 measurements and audio
node share/choir-studio/examples/benchmark.cjs  # local timing and post-run memory (not Windows)
# Optional: python3 share/choir-studio/examples/extract-long.py /path/to/local/VocalSet/source/vocalset
node --test share/choir-studio/tests/*.test.cjs
```

Windows portable CI runs the same tests and checks that the offline sidecar and examples are inside the extracted package. The portable verification script also checks MuseScore itself launches and exports a WAV with network blocked. This does **not** test microphone permission, browser UX or perceptual quality.
