# Personal Voice Choir Studio — experimental offline sidecar

**Status: proof of concept, not a finished in-app choir instrument.** No claim of realistic voices. One recorded human vowel can now be routed through solo, unison layers or four *written* parts; the demonstration also includes four separately recorded licensed singers. These excerpts have been **objectively measured for F0 only**; there has been no controlled human listening evaluation of realism, vocal age, register character or artifact severity. The examples include both synthetic tests and real recorded singing vowels with explicit [CC BY 4.0 attribution](examples/vocalset/ATTRIBUTION.md). This experimental sidecar deliberately avoids modifying MuseScore's audio engine, mixer, score or project storage until sound quality and score-event fidelity can be evaluated.

## Run offline

1. In MuseScore, open a score and export a **MIDI** file (File → Export → MIDI). A single note-bearing track is enough for solo or an independently written Bass-only/other single-part render; include four distinct tracks only when rendering all four SATB parts together. If playback-dependent details matter, audition the exported MIDI: this tool uses the MIDI's note-on/off, velocity, and tempo events as its sole timing/pitch authority, **not** the live score renderer. Some engraving semantics (fermata duration, articulation, historically marked dynamics) may be lost or simplified by MIDI export. This tool does not promise to preserve them beyond what MuseScore exports.
2. In the portable Windows ZIP, extract it and choose **Help → Personal Voice Choir Studio (experimental)…** in MuseScore. This opens the bundled `App/MuseScore/choir-studio/index.html` in your default browser. Alternatively open that file directly; from a source checkout, open `share/choir-studio/index.html`. No server, install, account, internet access, models or remote assets are required. Microphone capture requires browser permission and a secure context; if denied, import a WAV. No data is transmitted by this page.
3. Record a clear, steady **vowel** or import your own singing WAV (under 90 seconds). For takes longer than 1.2 seconds, the page scans the first 8 seconds for a stable voiced region and selects one ~240 ms vowel automatically. This uses a bounded pitch/level heuristic, **not** word or syllable recognition; verify the selection and choose the vowel start/end per part to override it. If no reliable region is found, the page warns you to select one manually. Enter source Hz if detection fails; import several vowels in different registers when possible. Switching a part to a different source resets stale crop/manual-Hz values. You can listen to and save the unchanged original separately from processed output. Browser microphone captures are commonly WebM or Ogg: **Save original capture** retains the exact capture; **Save reimportable WAV** exports a 24 kHz mono PCM copy you can load again. In-memory session data is cleared when you close/reload the page; **Save self-contained session** embeds the original recordings, MIDI, tags and settings in a local `.choir.json` file to reopen later. The processed WAV is exported separately.
4. Load the exported `.mid` file and choose an arrangement:
   - **Solo (default):** choose one written melody track, your recorded source and the voice character (including Bass). Only that part is rendered; no other track is required.
   - **Independent written parts (1–4):** click **Bass only**, another voice-only quick choice, or **All four**, or toggle **Include this part in the mix** on any combination (for example Alto + Bass). Each *audible included* part needs its own note-bearing MIDI track; disabled/muted parts need no track or recording for the current render, and Solo can temporarily isolate an included part. The Bass-only button follows Bass's mapped written track, **not** a transposed Soprano. A single MIDI track named Bass maps to the Bass card automatically; if the export uses generic names, choose the correct track manually before rendering. All four requires four distinct tracks; duplicate/missing included tracks fail visibly rather than inventing harmony. The shared-source button may put one recording on all four characters, or select different takes for different included parts.
   - **Unison layers:** choose one written melody and one recording; only the characters with **Include** checked follow those same notes. This is explicitly **not SATB harmony**, and is not a claim of four distinct singers. Write/assign independent parts in the score to move from solo to SATB. The page does not generate harmony from a solo melody or transcribe recorded singing.
   Each character has independent inclusion, pitch correction, approximate formant, brightness/warmth/breathiness/resonance/strength, volume/pan, variation, temporary mute and solo. In solo/unison the shared source and melody selectors override the per-part source/track selectors; in SATB those per-part selectors apply. A 100% correction target matches the MIDI pitch approximately; below 100% is intentionally expressive **and no longer guarantees written pitch**. The formant control is an approximate spectral shaping parameter, **not independent measured formant tracking**.
5. Optionally switch on **Use tagged singing ranges**. Choose a part, click **Guess sequential ranges** as a starting point, then select each written note and drag over its matching source range on the waveform (zoom with waveform from/to), or enter source start/end seconds and optionally that segment's Hz. Move a tag ±50 ms, listen to its unchanged source, and correct it. Tags are keyed by written track and source recording; in independent-part mode tag only the included audible tracks (all four only when all four are included), in solo just one. No automatic syllable alignment is performed. Save your work with the session button; the file embeds original recording bytes and the MIDI, not merely links to them. The session is limited to 16 recordings, 24 MB per original, 96 MB total source bytes and 5 MB of MIDI; larger files must be shortened before saving.
6. Render the complete score when it fits within the explicit **4-minute memory limit**; longer scores fail with an error rather than silently losing later notes. Changing the source, arrangement or voice controls invalidates the last processed WAV, so you cannot unknowingly download an obsolete mix. Listen against the original and download a 24 kHz stereo WAV. When the output-to-source pitch ratio exceeds 1.7 or is below 0.59, use a closer-register recording. Warnings do not mean the result will sound natural within the range. The vowel mode cannot produce lyrics; tagged mode retains only short unpitched attack/release portions of each *manually selected* source segment, not reliable full-word synthesis or trained vocal identities. Playback and export are performed entirely in browser memory; the processed WAV is not injected into MuseScore playback or stored inside the session file.

## Tagged recorded singing, source movement and stretch

**Manual phrase mapping is now implemented in the offline sidecar:** for each written MIDI note you can tag a distinct time interval in the unchanged singing take. The waveform, numeric start/end, ±50 ms nudge, 20-note pages and individual source preview make it possible to adjust the tags under notes without transcribing from the recording. A first guess distributes the recording in proportion to written note lengths; it does **not** recognize words, breaths or syllable boundaries. During rendering, each tag's ~35 ms original attack and ~25 ms original release (bounded by source/note length) flank a pitch-shifted period-synchronous center that traverses the tagged source and is fitted to the *written note duration*. The score still controls rests, onsets, pitch, velocities and tempo. A shift outside the recommended register or time stretch outside 0.4–2.5× warns. This is neither a verified consonant-preserving algorithm nor an automatic lyrical singer; listen and correct every tag. Each row now has **Hear tagged source** and **Hear pitched + stretched note**; the second uses the same note renderer as the export (isolated, at the written duration). The linked score timeline shows each note's pitch/name, written onset and rest gap, and the source waveform shows its tagged recording interval. Paging keeps dense scores usable.

The [before recording](examples/vocalset/tenor-m2-long-a.wav) and [after tagged WAV](examples/after-tagged-real-tenor.wav) are a real, CC BY 4.0 **vowel**, tagged twice for two separate Tenor notes with a rest. Download the [self-contained tagged session](examples/tagged-real-tenor.choir.json) and open it in step 5 to adjust the ranges and rerender without first importing the source and MIDI separately. [Objective F0 and tag measurements](examples/tagged-real-tenor-metrics.json) are −0.5 and +2.8 cents on the sustained notes. This validates note routing, not lyric or perceptual quality. Reproduce with `node share/choir-studio/examples/evaluate-tagged.cjs`. The session project file includes exact original blob bytes, pitch edits and settings and can be reopened offline; output WAV remains separate. This saves the **sidecar session**, not a native MuseScore score project.

## Explicit note pitch and key shifts (not automatic reharmonization)

Use the note row's **Output pitch** selector to audition and save a change such as written A4 → output B4. The MIDI score remains unmodified; the note-specific semitone edit applies to that written track across all parts using it. Choose **Score's original key** and **Output key** for a whole-arrangement same-mode transposition. For example, **A minor → G minor** shifts every independent part down two semitones; individual note edits travel with that transposition. The target-key guide displays G, A, B♭, C, D, E♭, F; a chosen B natural is permitted but marked chromatic. You may add an octave offset. Major → minor is *not* a simple key transposition and is rejected rather than silently reworking the harmony. Actual bass character is not guaranteed by lowering MIDI pitch. The saved `.choir.json` includes both global key settings and per-note edits; reopening preserves them, while the source MIDI remains unchanged.

Listen to a [licensed original singer](examples/vocalset/soprano-f1-long-a.wav), the [tagged A4→B4 result](examples/after-tagged-A4-to-B4.wav) and the [A-minor→G-minor result](examples/after-tagged-A-minor-to-G-minor.wav). [F0 measurements](examples/pitch-edit-metrics.json) for these two-note vowel examples are −3.0/−2.4 and −1.6/+2.1 cents respectively. These numbers are **not** perceptual singing or lyric-quality scores. `node share/choir-studio/examples/evaluate-pitch-edit.cjs` regenerates the audio and metrics. Do not use timbre/formant controls as a hidden way to retune the notes; pitch edits are separate and explicit.

## Single-voice solo-to-choir experiment (and its limits)

The attributed `examples/vocalset/tenor-m2-long-a.wav` (~0.8 s of one real singer's vowel) can be imported **once** with `examples/four-independent-real-registers.mid`. Render it as a Bass solo, unison on the Soprano melody, then assign the same recording to all four independent parts in SATB mode. Reproducible before/after WAVs are `examples/single-source-solo-bass.wav`, `examples/single-source-unison.wav` and `examples/single-source-four-written-parts.wav`; run `node share/choir-studio/examples/evaluate-single-source.cjs` to regenerate and inspect [F0 measurements](examples/single-source-metrics.json). First-note F0 errors for S/A/T/B are −0.8/−0.6/−0.4/−1.5 cents. **The soprano and bass shifts trigger extreme-register warnings**: numerical pitch accuracy here does not imply plausible soprano/bass timbre, different singers, retained syllables or musical naturalness. The input recording's CC BY 4.0 provenance and hash are in [ATTRIBUTION.md](examples/vocalset/ATTRIBUTION.md). This is not a conversion of an entire solo phrase with words into a convincing choir.

## Real-singer proof and its limits

Four attributed VocalSet singers are bundled **only as an optional offline demonstration**, not as an implicit default voicebank. Prefer the four `*-long-a.wav` files in `examples/vocalset/`: import them together, inspect the source assignment and load `examples/four-independent-real-registers.mid`. For a direct before/after, play `examples/vocalset/soprano-f1-long-a.wav` then `examples/after-long-soprano-A4.wav`; `examples/four-part-long-vowel-mix.wav` is the complete example. It has four distinct note tracks including bass A2, and uses source excerpts nearer each register. **Original source clips, exact hashes, offsets, licence and processing changes** are listed in [ATTRIBUTION.md](examples/vocalset/ATTRIBUTION.md). You may choose your **own** recording instead.

`node share/choir-studio/examples/evaluate-long.cjs` reproduces the longer-excerpt mix and [objective measurements](examples/long-vowel-metrics.json). On four isolated steady first notes, measured F0 errors are −0.2, −1.6, −0.4 and −1.1 cents respectively at 24 kHz; no extreme-shift warning. The previous 80 ms clips and their [short-clip measurements](examples/real-vowel-metrics.json) are retained for contrast, **not recommended as a natural-sounding voicebank**; the short alto excerpt triggers an extreme-shift warning. These measurements establish neither natural timbre nor perceived pitch on attacks or rapid phrases. **A proper blind perceptual evaluation using longer consented phrases, cross-register singers, listeners and phonetic material remains outstanding.**

The renderer uses a small, deterministic period-synchronous overlap-add grain process and simple filters. Grain spacing targets written F0 while source grains play at their original sample rate. Local waveform-phase correlation tracks the singer's period variations and is cached across notes; this fixes accumulated phase drift observed with the longer excerpts. Unlike a full PSOLA implementation, it does **not** identify glottal closure instants, handle consonants, de-ess or track time-varying formants. It can phase, buzz, sound synthetic, or shift pitch at attacks, and estimates a *single* steady source F0. Synthetic tests establish approximate sustained-note pitch, timing, non-silence, mute/solo and output-byte determinism; they do not establish perceptual quality. Playback of rapid tempo transitions and very short notes has not been perceptually validated.

## What “stable singing from my recording” still requires

Vowel mode maps MIDI events to a selected vowel. Tagged mode can instead map manually chosen portions of a sung take to notes, but **does not automatically align or preserve a complete lyrical phrase**. The following are separate milestones; none is implied by a low F0 error:

1. **Reliable single-part performance:** collect consented, longer recordings with different pitches, words, breath and attacks; evaluate note onset/duration, correct F0, silence during rests and audible artifacts against the *actual* score. A detected steady vowel only solves the source-selection step. Do not guess missing phonemes from a single sustained sample.
2. **Bass and four characters:** record source material in appropriate registers or use a separately licensed, offline voice-conversion/singing model with verified redistribution and Windows CPU requirements. Current presets are filters, not four trained identities; one tenor vowel shifted to bass is a test case with a warning, not an acceptable natural bass result. Keep each part's score events authoritative and its character controls independent of pitch.
3. **Full lyrics and articulation:** go beyond the manual source ranges and short original attack/release snippets here: align actual recorded syllables/phonemes to each written note (or collect a compatible voicebank), including multi-note syllables, consonant onsets, sustained vowels, ties and rests. Without this layer, arbitrary lyrics cannot be recovered from a single recording. Investigate score syllable events rather than inventing text from waveform pitch; do not introduce a network dependency.
4. **Native feature and release gate:** replace the external sidecar/MIDI export with processed note events through the MuseScore playback architecture, native score-project persistence and undo (the new `.choir.json` saves only the browser session), offline first-launch Windows package checks and consent/licence checks for every bundled asset. Validate browser microphone permissions and the native path on Windows, compare recordings with blind listeners across all four ranges, and only then claim stable or convincing choir singing. GitHub Actions is currently disabled, so this gate has not been met.

## Why not bundle a third-party processor or vocal model?

The following upstream primary sources were read in November 2026; none of these components is included here. Licensing and Windows feasibility alone cannot establish expressive quality.

| Approach | Verified terms & Windows evidence | Quality and resource tradeoff |
| --- | --- | --- |
| [Rubber Band Library](https://github.com/breakfastquay/rubberband/blob/master/README.md) | Its README states GPL version 2 **or later** (compatible in principle with this GPLv3 application when using that option), or commercial licensing; its [build guide](https://github.com/breakfastquay/rubberband/blob/master/COMPILING.md) documents Windows builds and a single-file built-in FFT/resampler option. Other FFT/backends have separate license obligations. | Offline professional time stretch/pitch shift option; **independent formant shifting and convincing choir output have not been verified here**. Native library adds build and CPU cost. |
| [aubio](https://github.com/aubio/aubio/blob/master/COPYING) | GPLv3 as indicated by its COPYING; its [README](https://github.com/aubio/aubio/blob/master/README.md) describes pitch analysis, phase vocoder and Windows AppVeyor. | Primarily analysis building blocks, not a turnkey singer; extra DSP implementation, FFT CPU and validation required. |
| [JUCE framework](https://github.com/juce-framework/JUCE/blob/master/LICENSE.md) | Its LICENSE.md describes **AGPLv3 or commercial** terms, not a blanket GPLv3 grant. It describes a cross-platform desktop framework. | Framework overhead, not by itself a licensed singing model or a formant-preserving transform. Not selected; AGPL integration review would be required. |
| Local browser-native PSOLA-like grains (implemented here) | This new source code is GPL-3.0-only like the project. Uses built-in browser Web Audio and MediaRecorder; no linked libraries or model assets. Four optional singers' short and longer vowel excerpts are separately licensed CC BY 4.0 with attribution; browser support and local-file microphone permissions vary. | Low installation cost; only a steady vowel and approximate spectrum; pitch metrics from four real vowels do **not** establish perceived quality. |

The existing MS Basic soundfont licence does **not** license use of any third-party singer samples. The eight included singer excerpts come from VocalSet, whose [primary Zenodo metadata](https://zenodo.org/api/records/1442513) confirms CC BY 4.0; their source transformation and hashes are documented alongside them. No unverified model or recording is bundled. To upgrade to a reliable in-app voice instrument: test multiple consented real recordings across each register, measure pitch/error and consonant preservation, assess timbre blind with listeners, investigate a redistribution-compatible processor and Windows build, then implement a per-track event source through the existing audio-engine interfaces and project persistence. Do not treat this sidecar as a completed replacement.

## Resource probe (not a Windows result)

On this Linux x64 sandbox with Node 22, `node share/choir-studio/examples/benchmark.cjs` rendered 960 synthetic note events across ~120 seconds of 24 kHz stereo score-aligned audio in about 0.25 seconds; resident process size changed from ~41 MB to roughly 85–100 MB in repeated runs. This is **not** a peak-memory measurement, browser timing, perceptual measurement or portable-Windows verification. The actual cost varies with score density, input length, device and browser. The 4-minute cap limits in-browser allocation; longer scores fail visibly instead of truncating.

```sh
node share/choir-studio/examples/generate.cjs  # regenerate the synthetic before/after WAV and MIDI
node share/choir-studio/examples/evaluate-real.cjs  # short-clip F0 measurements; NOT realism
node share/choir-studio/examples/evaluate-long.cjs  # longer-excerpt F0 measurements and audio
node share/choir-studio/examples/evaluate-single-source.cjs  # single singer solo/unison/SATB F0 and WAVs

node share/choir-studio/examples/evaluate-pitch-edit.cjs  # A4→B4 and A-minor→G-minor before/after WAVs
node share/choir-studio/examples/benchmark.cjs  # local timing and post-run memory (not Windows)
# Optional: python3 share/choir-studio/examples/extract-long.py /path/to/local/VocalSet/source/vocalset
node --test share/choir-studio/tests/*.test.cjs
```

The lightweight `Check: Offline Choir Studio` workflow runs the Node suite on Linux and Windows for pull requests, independently of the full Windows build. The portable Windows build additionally checks that the offline sidecar and examples are in the extracted package, then launches MuseScore and exports a WAV with network blocked. **GitHub Actions is disabled for this fork**, so neither workflow can currently run on GitHub; a base-branch merge will not enable it. Turn Actions on in the repository settings before treating either Windows check as passed.

A local **Linux headless Chromium** walkthrough of the actual `file://` page (with explicit local-file-access/permissive browser flags) exercised MIDI/WAV upload, original playback, single-track Bass and all-four rendering, Alto+Bass, unison, manual-tag mode (including missing-tag rejection), per-note and key edits, source/processed note preview, WAV download, self-contained session reload and byte-identical rerender. A second walkthrough used a **fake microphone device** to record, save the original WebM and export/reimport WAV. These are functional browser checks, **not** default-browser security-policy behavior, Windows portable first-launch, real microphone hardware, listening quality or native MuseScore playback validation. On Windows, manually extract the portable ZIP, launch `MuseScorePortable.exe` offline, open Help → Personal Voice Choir Studio, import a MIDI and WAV, audition both previews, render/download, save/reopen the session, and try microphone permission in the default browser; do not claim that gate passed until performed.
