## Immediate Chanukah workflow (before further engineering)

1. Enter an 18-staff/part test excerpt by hand from the musician's reading (do not upload the manuscript); use separate parts/voices as required. Set numerical BPM where known, and keep original Italian/German wording on the score. Enter pitches and rhythms first, then lyrics, then instructions. Duplicate/rename existing instrument templates rather than inventing an instrument file for each singer.
2. Use the existing Tempo, Dynamics, Articulations, Ornaments, Repeats & jumps palettes (search `Ctrl+F9`, default note-name input `N`, duration input `M` in `src/app/configs/data/shortcuts.json`; user shortcut configuration may override). The new search aliases find the *existing* tempo cells; they do not change the engraved text or assign a historical interpretation. Drag or apply the result with existing palette behavior. For `poco rit.` use the new typed `Poco rit.` palette cell, then adjust its initial 90% arrival factor and span to the musician's interpretation; its original printed wording remains separate from the factor. The analogous `Molto rit.` starts at 60%. These numbers are editable examples, not historical constants. Record the chosen interpretation outside the manuscript transcription.
3. For absolute tempo text (e.g., `Langsam`, `Nicht sehr langsam`) where no numerical value is specified, ask the musician for a BPM in *this passage*. Enter a Tempo Text with that BPM, turn off follow-text parsing when using the original words, and edit the printed wording separately. Do not convert `Langsam` to `Lento` automatically. `a tempo` and `tempo primo` have distinct built-in functions; inspect the resulting BPM after repeats and ramps.
4. Save native `.mscz` as the authoritative working copy. Make a short rehearsal export with the existing audio renderer and (separately) MIDI and MusicXML; compare an 18-part onset/tempo trace against playback rather than assuming the export has identical semantics. Start with available local SoundFont sound sources; defer specialized choir samples and singing until notation/timing is signed off.

### Playback classification (source-informed, not sound-verified)

* Functional timing: TempoText with `PLAY`, typed gradual tempo change and its configured length/factor, fermata stretch, some repeat/jump paths (see repeat fixtures), explicit rhythmic notes. With `followText` enabled, `a tempo` inserts the current discrete tempo at that tick to interrupt a progressive ramp (the code describes it as resetting to the previous tempo); `tempo primo` restores the first captured absolute tempo (or default). Neither implies that editing visible wording should automatically change the tempo. Both require passage-specific checking.
* Partial: named Italian absolute tempo cells carry fixed *editable* BPM presets, not historical truth; `rit.`, `rall.`, `calando`, `morendo`, `stringendo` etc. create tempo curves, **not necessarily** all the dynamic/phrasing connotations. Dynamics/hairpins affect dynamics automation; ornaments/legato/staccato depend on renderers, sound profile and notation. Existing source tests include `src/engraving/tests/tempotimeline_tests.cpp`, `src/engraving/tests/playback/playbackmodel_tests.cpp` and `src/engraving/tests/playback/playbackeventsrenderer_data/`; those are references, not tests executed here.
* Visual/unknown: untyped custom staff/system text such as `Con forza`, `Con molto` or `Nicht sehr langsam` has no inferred performance. Lyrics in `playbackcontext.cpp` are text syllable events; installed sound sources have not been shown to pronounce Hebrew. A palette glyph alone is not proof of sound support.

## Term-by-term triage (never silently normalize manuscript wording)

`Search` means the first-pass alias search added here; `cell` means an upstream palette cell. The musician must decide ambiguous semantics and numerical settings. `Partial` below means *a specific playback dimension exists*, not a complete musical performance. Where a term has no exact matching palette cell, use original visual text plus an explicitly configured functional marking if appropriate.

The focused hosted unit test checks that an unconfigured custom dynamic adds no point, that setting velocity 96 adds a 0.575 point without suppressing a following mp, and that disabling playback removes the point. Legacy MIDI now also respects the dynamic's playback toggle. A custom dynamic with an authored velocity can serve as a snapped hairpin target in the native automation curve; a focused test checks its arrival and out levels. These new tests have not yet run on the new commit.
